    - **Go**: Follow idiomatic Go: prefer composition over inheritance, explicit error handling over panic, and small focused interfaces. Never ignore errors; wrap them with `fmt.Errorf("context: %w", err)`. Use `context.Context` for cancellation and deadlines everywhere I/O crosses a boundary. Structure projects by domain package, not by layer. Prefer table-driven tests. Use `go vet` and a static analysis tool in CI. Keep goroutines owned and cancellable; document goroutine lifetimes. Prefer channels for communication, mutexes for shared state.
