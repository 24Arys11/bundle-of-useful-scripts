    - **MongoDB**: Design documents around access patterns, not normalisation. Embed when data is read together and written together; reference when data is shared or grows unboundedly. Use schema validation (`$jsonSchema`) to enforce structure at the database level. Apply indexes on all query fields; use compound indexes following the ESR rule (Equality → Sort → Range). Never store ObjectIds as strings. Use multi-document transactions only when atomicity across collections is truly required. Monitor with `explain("executionStats")`. Use change streams for event-driven patterns instead of polling.
